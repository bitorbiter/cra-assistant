# ADR-0000: Title in one line, stating the decision

- Status: proposed | accepted | superseded by [ADR-NNNN](NNNN-title.md)
- Date: YYYY-MM-DD

## Context

What forces us to decide? The problem, the constraints that are not negotiable,
and anything a reader needs in order to judge the decision fairly. Written so
that someone joining the project in a year understands the situation without
reading the code first.

## Decision

What we are doing, in the active voice and in one or two sentences.
"We will ..." — concrete enough that a reviewer can tell whether the code
follows it.

## Rationale

Why this option and not the others. Name the property that decided it. If the
decision was close, say so; if it was forced by a constraint, name the
constraint.

## Consequences

What becomes true once this is in place — the good and the bad, in the same
list. Include the cost: what gets harder, what we can no longer do cheaply,
what we will have to revisit and under which trigger.

## Rejected alternatives

### Option A

What it was, and the specific reason it lost. Not "it was worse" but the
property that failed.

### Option B

Same. Include options that were tempting; a rejected alternative nobody
considered is not worth recording.

## Notes

Links to sources, spikes, measurements or discussion that informed the
decision. Optional; delete this section if empty.
